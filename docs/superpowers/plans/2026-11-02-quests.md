# Player Quests Implementation Plan

**Goal:** Implement 300 permanent quests, merit and 12 selectable fun titles.

**Architecture:** Server-authoritative observations of validated room activity update SQLite-backed progress. All 300 quests remain available, with cumulative lifetime progress and no reset or daily limit. Completed rewards never repeat. A compact entry button opens a responsive quest dialog. Titles never replace player names.

**Tech Stack:** Existing TypeScript, Colyseus, node:sqlite, React, Vite.

**Approved scope:** User correction: exactly 300 continuous quests, no daily rotation, swaps, streaks or resets. Build on the 15 activity families already discussed, with 20 permanent goals per family. Social quests are optional and never gate other quests. Never count raw client claims as progress. Cumulative goals may complete together; each reward is permanent and granted once.

- [ ] Add the 300-quest catalog, progress engine, persistence and tests for one-time rewards, ongoing progress and unlocked titles.
- [ ] Observe completed actions, real seated time, movement, visits and meal lifecycle on the server; test interrupted actions and prayer counts.
- [ ] Send progress privately and equipped titles publicly; validate quest requests server-side.
- [ ] Add responsive quest/merit/title UI with live progress and reward feedback.
- [ ] Run backend and frontend checks, builds and UI regression tests; review final diff.
